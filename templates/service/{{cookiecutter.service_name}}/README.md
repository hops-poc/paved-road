## Before your first deploy

The gates are only real once enforcement is anchored outside the diff — a policy in this
repo can be deleted by the PR it would block. In repo settings, not in code:

1. Required status checks on `main` for the gate jobs, plus a repo ruleset.
2. `CODEOWNERS` review required on `.github/`, `infra/`, and `policies/`.
3. `dev` and `prod` GitHub Environments, with `prod` requiring a human reviewer.

Pin bumps to a newer `paved-road` SHA go through a normal PR, like any other change.

See `paved-road`'s `DECISIONS.md` (why each gate blocks or reports) and
`AI-GOVERNANCE.md` (what the agents may and may never do).
